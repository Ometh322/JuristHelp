# Правовой Стандарт — сайт юридических услуг

Демо-сайт для продажи юридических консультаций, платных статей, шаблонов договоров и обучающих курсов. Под каждым товаром — QR-код для оплаты.

## Структура

```
index.html                          Главная (hero + форма, услуги, статьи, шаблоны, курсы, отзывы, FAQ, CTA)
uslugi.html                         Услуги консультаций — 7 услуг с ценами и QR
stati.html                          Каталог платных статей + подписка
stati/*.html                        5 статей: бесплатное вступление + платная часть под пейволлом
shablony.html                       8 шаблонов договоров + комплект, QR у каждого
kursy.html                          4 обучающих курса с программами и QR
assets/css/style.css                Все стили (дизайн-система: navy + gold)
assets/js/payments.js               ★ Конфиг товаров, цен и платёжных ссылок
assets/js/main.js                   Логика: QR, окно оплаты, пейволл, меню, формы
assets/js/vendor/qrcode.min.js      QR-библиотека (работает офлайн)
```

## Как устроена оплата (статичный QR СБП)

К сайту подключена **статичная ссылка QR СБП (НСПК)** — `PAYMENT_SETTINGS.staticPayUrl`
в `assets/js/payments.js`. Все QR-коды на сайте (услуги, статьи, шаблоны, курсы)
строятся в браузере из этой одной ссылки.

Особенности статичного QR, которые учтены в текстах сайта:

- **Сумма не подставляется автоматически** — покупатель вводит её вручную в
  приложении банка. Окно оплаты показывает точную сумму и предупреждает об этом.
- **Нет автоматической выдачи** — после оплаты покупатель присылает скриншот чека
  на почту/телефон, вы вручную отправляете код доступа (для статей) или файлы
  (для шаблонов/курсов). Демо-коды: `DEMO-S1`…`DEMO-S5`, `DEMO-SUB` и т.д. — см. `payments.js`.
- Код доступа снимает пейволл статьи и сохраняется в localStorage браузера покупателя.

### Когда захотите автоматизировать приём платежей

1. Динамические QR СБП или ссылки ЮKassa/Т-Банк Кассы формируются на каждую оплату
   с зашитой суммой — добавьте поле `url` у нужного товара в `PRODUCTS`, и QR для
   этого товара станет уникальным автоматически.
2. Автовыдачу кодов сделает только бэкенд: платёжный вебхук → генерация кода →
   письмо покупателю (и проверка кода на сервере, а не в клиентском JS).

### Честное ограничение текущей версии

Пейволл — клиентский: платный текст физически присутствует на странице (размыт
CSS), коды зашиты в `payments.js`. Для строгого разграничения доступа нужен бэкенд
или платформа (GetCourse/Boosty/Ghost).

## Запуск локально

Статический сайт, любой веб-сервер, например:

```bash
# Python
python -m http.server 8080
# или Node
npx serve .
```

Открыть: http://localhost:8080

## Деплой

Загрузите папку целиком на любой статический хостинг: REG.RU/Beget (обычный
виртуальный хостинг), Netlify, Vercel, Cloudflare Pages, GitHub Pages. PHP/Node
не требуются.

## Добавление нового товара

1. Добавьте запись в `PRODUCTS` (`assets/js/payments.js`): id, название, цена, код.
2. Скопируйте карточку товара на нужной странице и подставьте новый `data-qr="id"`
   и `data-buy="id"` — QR, цена и окно оплаты соберутся сами.
